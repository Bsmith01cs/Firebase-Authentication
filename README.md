# Firebase Authentication App — CSC 4360 In-Class Activity #13

Repository: https://github.com/Bsmith01cs/Firebase-Authentication

A minimal Flutter app demonstrating Firebase Email/Password authentication:
registration, sign-in, authentication-state routing, a protected profile screen,
sign-out, and password updating with reauthentication.

## Features

- **Register / Sign In** — one screen toggles between both modes, with email format
  validation and a six-character minimum password.
- **Auth-state routing** — `AuthGate` listens to a single stable `authStateChanges()`
  stream and shows the authentication screen when signed out, the profile when signed in.
  No manual navigation is used, so sign-out returns to the sign-in screen automatically.
- **Protected profile** — displays the signed-in account's email.
- **Change password** — dialog taking the current and new password; reauthenticates
  automatically when Firebase reports `requires-recent-login`.
- **Sign out**.

## Project structure

```
lib/
  main.dart                        Firebase init + MaterialApp(home: AuthGate)
  firebase_options.dart            generated by flutterfire configure
  services/auth_service.dart       all FirebaseAuth operations
  screens/auth_gate.dart           StreamBuilder<User?> routing
  screens/authentication_screen.dart   register / sign-in form
  screens/profile_screen.dart      profile + change-password dialog
```

## Firebase setup

The app targets Firebase project `intro-firebase-2ee9f`, Android package
`com.csc4360.firebase_auth_app`. To run it against your own project:

1. `dart pub global activate flutterfire_cli`
2. `flutterfire configure` and select the project and the Android platform.
   This regenerates `lib/firebase_options.dart` and `android/app/google-services.json`.
3. In the Firebase Console: **Authentication -> Get started -> Sign-in method ->
   Email/Password -> Enable -> Save**.

Step 3 is required. Without it every authentication call fails with
`CONFIGURATION_NOT_FOUND`, because the project has no Identity Toolkit configuration.

`android/app/src/main/AndroidManifest.xml` declares `android.permission.INTERNET`.
The Flutter template declares it only for debug and profile builds, so release builds
cannot reach Firebase without this entry.

### A note on the committed Firebase config

`lib/firebase_options.dart` and `android/app/google-services.json` contain the project's
Android API key. These are client identifiers rather than secrets and are committed by design
in a FlutterFire project; access is controlled by Firebase Authentication and Security Rules,
not by hiding the key. No keystore, `key.properties`, or signing material is in this repository.

## Manual test instructions

Firebase Authentication cannot be exercised without real credentials, so these steps
are run by hand against a test account.

1. **Validation** — enter an invalid email and a password under six characters; both
   fields show inline errors and no network call is made.
2. **Register** — enter a test email and a six-character-plus password, tap
   *Create Account*; the profile screen appears showing that email.
3. **Session restore** — force-stop and relaunch the app; it returns to the profile
   without prompting for sign-in.
4. **Sign out** — tap *Sign Out*; the sign-in screen returns and the profile is no
   longer reachable.
5. **Wrong password** — sign in with an incorrect password; the screen shows
   "Incorrect email or password."
6. **Sign in** — sign in with the correct password; the profile appears.
7. **Change password** — tap *Change Password*, enter the current and a new password;
   the dialog closes and a "Password updated." snackbar appears.
8. **New credentials** — sign out, confirm the old password is rejected and the new
   password succeeds.

Results observed during the in-class activity: tests 1, 2 and 3 passed, along with the
Change Password dialog's rendering and its required-field validation. Tests 4 through 8 and the
`requires-recent-login` recovery path were not run and are not claimed to work.
